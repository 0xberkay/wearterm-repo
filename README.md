# zbd package repository

The package feed for Wear Term. It costs nothing to run: the index is a static JSON file on
GitHub Pages, the archives are GitHub Release assets, and GitHub Actions does the building.
There is no server.

## How it works

`tools/build_repo.py` downloads upstream Termux `.deb` packages for `aarch64` and `x86_64`,
rewrites the install prefix, and republishes them as `.zbd` archives.

The prefix rewrite is the reason the app's application id is **`com.zbd.wt`**. Termux bakes
`/data/data/com.termux/files/usr` into binaries as an absolute path, and `com.zbd.wt` is
exactly as many bytes as `com.termux` — so the path can be replaced *in place* inside ELF
files, scripts and data files without moving a single byte. No `patchelf`, no `proot`, no
ptrace overhead, and packages keep working unmodified.

A `.zbd` archive is a gzipped tar (gzip because `java.util.zip` is already in the platform, so
the client needs no archive dependency):

```
manifest.json          name, version, arch, deps, license, sourceUrl
files/                 the tree to unpack into $PREFIX
post-install.sh        optional, run by the shell after unpacking
```

The synthetic `bootstrap` package merges the core userland — bash, busybox, coreutils, ncurses,
readline — into a single archive plus `etc/profile` and the `zbd` shim, so first run is one
download rather than a dozen.

## Setting it up

This repository is already set up and serving; the steps are here for anyone forking it.

1. Put this directory at the root of its own GitHub repository (public, so Pages and Releases
   are free). `.github/workflows/build-repo.yml` has to sit at the repository root to run, and
   pushing it needs a token with the `workflow` scope.

2. Enable **Settings → Pages → Source: GitHub Actions**.

3. Run the `build-repo` workflow. It publishes `index-arm.json`, `index-aarch64.json` and
   `index-x86_64.json` to Pages and uploads the `.zbd` archives to a rolling release tagged
   `repo`. The `arm` index is the one 32-bit-only watches need.

4. Point the app at it: set `DEFAULT_BASE_URL` in
   `app/src/main/java/com/zbd/wearterm/pkg/Repository.kt` to your Pages URL, e.g.
   `https://<user>.github.io/wearterm-repo`.

Edit `packages.list` to change what is published; dependencies are resolved automatically.

## Running it locally

```
python3 tools/build_repo.py --arch aarch64 --out dist --asset-base https://example.test/dl
```

## Scripts

[`scripts/`](scripts) holds small `sh` helpers written against the app's `wt-*` device
commands. The build publishes them to Pages beside the package index, at
`https://0xberkay.github.io/wearterm-repo/scripts/`, with `scripts/index.json` naming each
one and carrying its SHA-256; the watch installs them from the app's Scripts screen and
verifies that hash before writing anything to `$PREFIX/bin`.

`index.json` is regenerated by the workflow, so the committed copy is a convenience only —
run `scripts/build-index.sh` after editing a script to keep them in step locally.

## Licensing

Nothing here is relicensed. Every package carries three fields so the source-availability
obligations of the GPL packages travel with the binaries:

| field | points at |
| --- | --- |
| `license` | `TERMUX_PKG_LICENSE`, read from the upstream build recipe |
| `sourceUrl` | the recipe itself — enough to rebuild the binary |
| `upstreamSourceUrl` | the original source tarball, when the recipe names one plainly |
| `binaryUrl` | the `.deb` the archive was repackaged from |

The apt index carries no `License` field and points only at the `.deb`, which is a binary and
so not the "corresponding source" a redistributor has to offer — hence the recipe lookup.
Packages that are subpackages of another recipe have no directory of their own and come out
with an empty licence; the build logs which ones.

The one modification made here is the prefix rewrite, and its complete source is
`tools/build_repo.py` in this repository.
